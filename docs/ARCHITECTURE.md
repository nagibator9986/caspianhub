# Архитектура Caspian College Hub

## 1. Постановка задачи

Цифровые сервисы Колледжа Каспийского университета разбросаны по разным платформам:
электронный журнал живёт на `college.snation.kz`, методические материалы и библиотека —
на сайте колледжа, вакансии — на `beam.kz`, справки — частично в учебной части, частично
на `egov.kz`. Студент вынужден держать все эти адреса в голове или искать их в чате группы.

**Задача платформы** — единое окно: одна точка входа, где каждый сервис представлен
карточкой с описанием, ответами на частые вопросы и коротким обучающим курсом.
Платформа не заменяет сервисы, а объясняет их и ведёт к ним.

## 2. Архитектурный стиль

Классическое серверное веб-приложение (SSR) на Flask с фабрикой приложения и разделением
на блюпринты. Выбор обусловлен требованиями:

| Требование | Решение |
|------------|---------|
| Быстрая отдача и SEO | Серверный рендеринг Jinja2 — страницы индексируются, не нужен JS для чтения |
| Простое развёртывание | SQLite в файле, без внешних служб; весь фронтенд вендорен локально |
| Полная редактируемость | Контент и оформление — в БД, а не в коде; админка строит формы по метаданным |
| Интерактивность без SPA | Alpine.js для локального состояния, fetch для точечных операций |

## 3. Слои приложения

```
run.py                     точка входа, создаёт приложение через фабрику
└── app/__init__.py        create_app(): конфигурация, расширения, блюпринты,
    │                      хуки запроса, фильтры Jinja, обработчики ошибок, CLI
    ├── extensions.py      db, login_manager, migrate, csrf — отдельно от фабрики,
    │                      чтобы избежать циклических импортов
    ├── models.py          предметная область (24 модели)
    ├── utils.py           настройки, Markdown, загрузка файлов, контроль доступа
    ├── i18n.py            строки интерфейса RU/KK/EN
    └── blueprints/
        ├── public.py      витрина: главная, каталог, сервис, новости, FAQ, поддержка
        ├── auth.py        регистрация, вход, выход
        ├── learn.py       курсы, уроки, прогресс, тесты, сертификаты
        ├── account.py     личный кабинет студента
        ├── admin.py       панель управления (CRUD по всем сущностям)
        └── api.py         JSON: живой поиск, избранное, учёт переходов
```

## 4. Модель данных

Основные связи:

```
Category 1──* Service 1──1 Course 1──* Module 1──* Lesson
                 │              │                    │
                 ├──* ServiceScreenshot              └──* LessonProgress ──* User
                 ├──* ServiceFaq                │
                 ├──*─* Tag                     └──1 Quiz 1──* Question 1──* Option
                 ├──* Favorite ──* User                          │
                 └──* ServiceEvent                                └──* QuizAttempt ──* User

Course ──* Certificate ──* User
```

Вспомогательные сущности: `Setting` (настройки сайта), `MenuItem` (конструктор навигации),
`HomeSection` (блоки главной), `News`, `Faq`, `Testimonial`, `Feedback`, `MediaFile`, `AuditLog`.

### Ключевые решения

**Мультиязычность суффиксами.** Вместо отдельной таблицы переводов или `.po`-файлов
переводимые поля дублируются как `name_ru` / `name_kk` / `name_en`. Примесь `Translatable`
даёт метод `tr('name')`, который возвращает значение текущего языка с откатом на русский.

*Почему так:* редактор правит все три языка в одной форме админки, без перекомпиляции
и без join'ов на каждый запрос. Цена — ширина таблицы; для 18 сервисов это несущественно.

**Настройки как данные.** Таблица `settings` хранит пары ключ-значение с полем `value_type`
(`text`, `textarea`, `color`, `image`, `bool`, `int`, `url`). Админка строит форму по этому
типу, а не по захардкоженному списку полей. Значения кэшируются в памяти процесса и
сбрасываются при сохранении.

Бренд-цвета из настроек подставляются в CSS-переменные `--brand` / `--brand-2` прямо в `<head>`,
поэтому смена цвета в админке мгновенно перекрашивает весь интерфейс — от кнопок до графиков.

**Контент как данные.** Описания сервисов, уроки, тесты, новости и FAQ лежат в `content/*.json`
и заливаются скриптом `seed.py`. Это позволяет пересобрать базу из читаемых исходников
и вести контент отдельно от кода.

## 5. Прикладная логика

**Прогресс обучения.** `Course.progress_for(user)` считает долю завершённых уроков.
Отметка урока идёт через `POST /learn/lesson/<id>/complete`, ответ содержит новый процент
и адрес следующего шага — страница обновляет прогресс без перезагрузки.

**Тестирование и сертификат.** Ответы сверяются на сервере (`Option.is_correct`), попытка
сохраняется целиком (`QuizAttempt.answers_json`) — это даёт разбор ошибок. При результате
не ниже `pass_score` выдаётся `Certificate` с уникальным кодом `CCU-XXXXXXXXXX`,
проверяемым по публичной ссылке.

**Аналитика.** Каждый просмотр страницы сервиса и каждый переход на внешний сайт пишутся
в `ServiceEvent`. Переходы фиксируются через `navigator.sendBeacon` — запрос успевает уйти
даже когда браузер уже уходит на внешний адрес.

## 6. Безопасность

| Риск | Мера |
|------|------|
| CSRF | `Flask-WTF` на всех формах; исключение — только endpoint учёта переходов (sendBeacon не передаёт заголовки) |
| Хранение паролей | `werkzeug.security` (PBKDF2 с солью) |
| XSS через Markdown | Рендеринг через `markdown`, затем санитизация `bleach` по белому списку тегов и атрибутов |
| Загрузка вредоносных файлов | Белый список расширений, лимит 16 МБ, имена заменяются на UUID, изображения пережимаются Pillow |
| Open redirect | `safe_next()` пропускает только относительные пути |
| Спам в форме поддержки | Скрытое поле-приманка (honeypot) |
| Повышение привилегий | Декораторы `staff_required` / `admin_required`; нельзя снять права с самого себя и удалить свою учётную запись |
| Кликджекинг, MIME-sniffing | Заголовки `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy` |

## 7. Интерфейс

**Дизайн-система** построена на CSS-переменных: палитра, тени, радиусы, кривые анимации.
Тёмная тема — переопределение тех же переменных, поэтому ни один компонент не требует
отдельной тёмной версии. Палитра взята с сайта колледжа: коралловый `#EB5A40`,
акцент `#F9A03F`, графит `#6D6D6B`.

**Анимации** подчинены содержанию: появление блоков при прокрутке (IntersectionObserver),
параллакс героя (GSAP ScrollTrigger), плавная прокрутка (Lenis), счётчики (CountUp),
конфетти при завершении курса. Всё отключается при `prefers-reduced-motion: reduce`.

**Автономность.** Tailwind, Alpine, GSAP, Swiper, Chart.js, шрифты Manrope и Inter —
всё лежит в `app/static/vendor` и `app/static/fonts`. Платформа полностью работает
без интернета, что важно для демонстрации и для аудиторий с нестабильной сетью.

## 8. Проверка качества

| Скрипт | Что проверяет |
|--------|---------------|
| `smoke_test.py` | Все маршруты для гостя, студента и администратора отдают корректный ответ |
| `crud_test.py` | Создание, изменение и удаление всех сущностей через формы админки; каскады; права доступа; honeypot |
| `layout_check.py` | Вёрстка в реальном браузере: горизонтальное переполнение, обрезанный текст, ошибки JS, тёмная тема — на пяти ширинах экрана |

## 9. Возможные направления развития

- Интеграция с SmartNation по API вместо ручного перехода по ссылке
- Уведомления студентам (почта, Telegram) о новых материалах и дедлайнах
- Экспорт сертификата в PDF на сервере вместо печати из браузера
- Перенос на PostgreSQL при росте числа пользователей
- Роль куратора с доступом к прогрессу своей группы
